# Очередь повторений NERIVA

## Цель

Дать ученику одно место для просмотра и выполнения повторений из уроков, AI-репетитора и ролевой практики. Первый этап предоставляет чтение расписания AI-репетитора из действующих хранилищ.

## Первый этап

- Авторизованный `GET /api/learning-reviews` возвращает объект `items` с массивом записей текущего аккаунта и языка обучения. У записи есть стабильный идентификатор, источник, идентификатор урока, заголовок, срок в UTC и состояние `due` или `upcoming`. Пустая очередь возвращает пустой массив.
- Срок сравнивается с серверным временем. Сначала идут самые ранние сроки, записи с одним сроком сортируются по идентификатору.
- Для одного урока используется последняя валидная запись расписания. При совпадении времени обновления применяется более ранний срок, затем идентификатор записи.
- Записи с неизвестным уроком или недействительным сроком пропускаются. Действующее сохранение расписания одинаково используется в вебе и Telegram. Схема базы и прежние маршруты остаются доступны.

## Критерии

Проверить выдачу просроченного и будущего уроков, фильтрацию по аккаунту и языку, дубли старых записей и HTTP 401 для гостя. Проверить существующие тесты AI-репетитора и SQLite.

## Экран «Сегодня»

На экране «Сегодня» выводится первое повторение из очереди. Для AI-репетитора срок отображается в часовом поясе устройства. По наступившему сроку пользователь с Premium может открыть конкретный урок существующим маршрутом повторного запуска. Сохранённая ошибка открывается в тренажёре без Premium. При активном уроке в текущем веб-приложении кнопка повторения отключена. Будущий срок показан без кнопки запуска. Если сервер недоступен или очередь пуста, блок не отображается.

## Завершение повторения AI-репетитора

- Успешное завершение сессии закрывает наступившие повторения того же урока и аккаунта. При выборе нового срока прежние активные записи этого урока заменяются одной будущей записью.
- В SQLite изменение расписания, завершение сессии и начисление XP проходят в одной транзакции. Идентификатор сессии служит ключом повторной отправки финального ответа. Повтор того же запроса оставляет сохранённый результат и срок в силе.
- Тесты проверяют откат при сбое начисления XP, повторную отправку, замену срока и изоляцию других уроков и аккаунтов. Для замены срока проверяются SQLite и JSON.

## Повторение сохранённых ошибок

- Ошибки обычных уроков, свободной и ролевой практики попадают в очередь через существующий словарь ошибок. Источник выдачи — `mistake`; старые записи участвуют по тем же правилам. Отдельная метка режима в словаре не требуется.
- Сохранённые ошибки готовы к повторению сразу. Очередь показывает сначала готовые задания, затем будущие.
- Тренажёр принимает стабильный `review_id` и разрешает его в рамках аккаунта и языка. При ответе ошибка повторно находится по тому же идентификатору, даже если позиция в словаре изменилась. Успешное исправление убирает запись из словаря и очереди.
- При отправке ответа веб-клиент передаёт `review_id`. Если упражнение уже завершилось или сменилось, сервер возвращает 409. В SQLite начисление 8 XP, удаление ошибки и закрытие упражнения проходят одной транзакцией. При сбое запрос можно повторить. Для старых клиентов идентификатор в ответе остаётся необязательным.

## Следующие этапы

Сохранённый счётчик виден в учебном прогрессе для текущего аккаунта и языка. Рядом отображается `completed_last_7_days` за скользящие семь суток по серверному времени, включая точную нижнюю границу периода. Повторное сохранение сохраняет первое время завершения. После перезагрузки оба значения заново читаются из профиля. При недоступности API карточка скрыта. Со старым API доступен общий счётчик.

Недельная сводка использует ту же очередь и те же правила запуска, что экран «Сегодня». При открытии упражнения используется его идентификатор. Если уже идёт урок или загружается учебное действие, кнопка запуска отключена.

Первый пилот даёт дополнительное упражнение после успешного исправления двух английских шаблонов: `I go → I went` и `she go → she goes`. В новом задании меняются глагол и контекст. Проверка принимает заданные варианты ответа с учётом регистра, пробелов и пунктуации, предлагает подсказку и позволяет открыть пример. Упражнение можно закрыть и вернуться к списку ошибок.

Пилот также распознаёт добавление `a/an`, исправление `we/they/you is → are` и замену прошедшей формы глагола после `didn't/did not` на начальную. Для этих правил проверяется, что остальная часть фразы совпадает после нормализации. Упражнения принимают перечисленные варианты, включая сокращения там, где они предусмотрены.

Результат проверяется локально. После верного ответа веб-клиент отправляет идентификатор исправленной ошибки в `POST /api/mistakes/transfer`. Сервер принимает только зарегистрированный после успешного исправления ID текущего аккаунта и языка, сохраняет первое время завершения, а при повторной отправке возвращает текущее число выполненных упражнений. `GET /api/mistakes/transfer` возвращает этот счётчик. Текст ответа и подсказки не отправляются. Запись не меняет XP и не используется для оценки уровня. После сбоя сохранение можно повторить из упражнения.
