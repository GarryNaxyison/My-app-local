# Web Functionality Matrix

This file tracks current behavior separately for desktop web and mobile web. `/app` is the main web experience; `/app/mobile` and `/app/desktop` force shell layouts for QA, and `/app/v1` plus `/app/v2` redirect to `/app` for old links. Keep this file updated before deploys that change user flows.

## Desktop Web

### Current Core Learning

- Today/Home: weekly plan, daily quests, progress snapshot, learning lab entries, habit calendar, and daily bonus claim.
- Lesson: starts an anti-repeat micro-task, shows structured AI output, corrected/model phrase audio, and quick-save phrase actions.
- Practice: keeps short learner context, shows only practice-scoped messages, supports text, voice, image/file controls, and quick-save phrase actions.
- Listening: presents target phrase, learner repeat, waveform playback, score, tips, and next phrase action.
- Learn Words / Review / Spelling: load active questions, show result cards, audio at the result stage, examples, and next actions.
- Vocabulary: dictionary-style cards with word, translation, CEFR/example/audio/status without review/spelling counters.
- Mistakes: grouped errors, correction history, correct-answer waveform audio, similar drill action, and clear confirmation.
- Awards: rank names and stories use the canonical shared copy.
- Premium: plan selection, payment requisites, timeline/history, payment check, success/not-found centered dialogs.
- Settings: profile, security/password, Telegram linking/two-factor popup, activation block under Telegram, global learning focus.

### New Web Additions

- Notes: personal saved phrases from lessons/practice plus manual additions, playback, note text, source labels, and remove action. The old Phrasebook/Phrases naming is intentionally replaced in the web UI.
- Habit calendar: month calendar with login days and green completed daily-goal days, plus current streak and monthly completion count.
- Daily bonus: once-per-day XP claim after the required daily activity is complete, with a visible bonus animation.
- Bug report: top-bar report button opens a centered dialog with description and optional screenshot upload; server stores a JSONL report and screenshot file.
- Offline grouping: Offline decks can show all cards, words, phrasebook, or mistakes and export JSON or readable TXT.
- New menu artwork: Roleplay, Pronunciation, Offline, and Phrasebook use generated light/dark assets in the same menu system.
- Web menu localization: the main menu, learning lab, Offline decks, Daily quests, Weekly plan, Daily route, Dashboard, Referrals, Roleplay, and Phrasebook labels have explicit clean translations for all supported interface languages.
- Today cleanup: the habit streak side panel is aligned to the right of the calendar on desktop, and the obsolete "Next features" recommendation block is removed.
- Pronunciation cleanup: the dashboard uses larger centered Pronunciation/Phrasebook artwork and a compact pronunciation map with short issue labels instead of repeated long advice on every token.
- Offline layout: desktop Offline decks use the available width with readable cards instead of leaving unused side columns.
- Payment history: visible history filters out created/pending invoices and keeps only confirmed/paid rows.
- Referrals: invited learners are listed with join date, level/XP, level-3 status, earned amount, and 10-row pagination.
- Offline pagination: saved cards show 10 per page, while TXT/JSON export still includes the full filtered deck.
- Menu artwork: Offline, Phrases/Phrasebook, Pronunciation, and Roleplay reference the current FLUX.2 transparent PNGs through a versioned `/app/assets/icon-...png?v=...` URL so desktop and mobile refresh together.
- Learn Words: answer options are generated by the shared backend vocabulary option path used by web and Telegram; wrong-answer sets must vary between rounds and remain unique within a question.
- Learn Words / Review: wrong-answer options are sampled from dictionary words in the same CEFR band as the correct answer (`A1/A2`, `B1/B2`, `C1/C2`) so web and Telegram do not recycle a fixed answer pool.
- Pronunciation history: weak words/sounds and score history are cached per account in the browser so the dashboard survives reloads even when the current message list is empty.
- Auth: `/login` and `/app/login` use the React web sign-in screen with the shared `SignInPage` UI component, while keeping `/api/auth/login`, `/api/auth/register`, Cloudflare Turnstile, and Telegram OTP login behavior. Registration and Telegram linking require personal-data policy consent, recovery opens `https://t.me/NERIVAapp_bot`, and auth card copy is localized for all interface languages.
- Privacy: the public privacy policy is generated for all 20 languages into the React site and legacy static asset path, and new Telegram users see Continue/Policy onboarding before profile setup.

## Mobile Web

### Current Core Learning

- The desktop top header and top ribbon are hidden on phones.
- Mobile uses fixed top-right quick controls: report bug, language, small theme icon, and icon-only logout.
- Mobile bottom navigation shows the primary destinations and a bottom-right More tab that opens the remaining menu sections.
- Chat/composer and trainer results stay in the same view surface; modals are centered and constrained for narrow screens.
- Audio, voice, image, and file controls use compact touch-sized controls rather than desktop-width toolbars.
- Dense mobile web views scroll through the main content surface; nested panels should not trap content in non-scrollable fixed-height blocks.

### New Web Additions

- Phrasebook cards stack in one column with full-width action rows and readable note/source metadata.
- Habit calendar is constrained to the panel width and keeps calendar cells touch-friendly.
- Daily bonus animation is fixed to the top center of the viewport so it does not push content around.
- Bug report dialog fits inside mobile viewports and accepts screenshots from the device file picker.
- Offline grouping uses horizontally scrollable compact chips and full-width study cards.
- New menu artwork follows the same light/dark asset path as desktop, while mobile cards keep labels readable and do not shrink icons on hover.
- More opens visual menu tiles with the same generated artwork as desktop.
- Bottom navigation is editable on mobile: long-press enters edit mode, X moves pinned items into More, tapping a More tile pins it back, and Done exits editing.
- Practice keeps its input/composer panel visible above the bottom nav. Tools uses a selector-first mobile flow: the user chooses translator, voice-to-text, or photo translation first, then the dedicated tool work window opens with the input panel.
- Onboarding/start dialog is height-constrained on phones and scrolls internally, keeping the goal/level/language/format controls and submit buttons reachable on short viewports.
- Lesson and Practice place compact Phrasebook quick-save actions after the composer/input block on mobile, so saved-phrase chips do not cover the output/task area.
- Roleplay hides the selected scenario brief on mobile after entry and leaves only the localized choose-another-scenario action above the dialogue.
- More edit mode supports dragging/reordering tiles inside More in addition to pinning and unpinning bottom-nav items.
- Tools hides the large tool selector after a tool is chosen and exposes a compact choose-tool button to reopen the selector.
- Mobile Today is the only section with top quick controls. Lesson, Practice, Tools, Roleplay, Mistakes, Premium, and other sections use the saved vertical space for scrollable output and input.
- Mobile payment requisites modals sit above the bottom navigation and use scrollable safe-area padding, so TON/USDT requisites and the check-payment action stay reachable.
- Award details open through a fixed viewport modal rendered on `document.body`; tapping a reward after scrolling keeps the details card in the currently visible part of the screen.
- Lesson and Practice keep the save-to-Notes/Phrasebook action inside the composer after voice/photo controls, not in a separate hidden block under the viewport.
- Roleplay hides the bulky selected-scenario heading on mobile and keeps only the localized choose-another-scenario action.
- Mistakes keeps the dictionary/drill list scrollable to the bottom on narrow screens.
- Browser Back on mobile is part of the in-app navigation contract: it should return to the previous V2 view instead of leaving the site.
- Active Roleplay on mobile keeps only a compact localized choose-another-scenario action above the dialogue; the bulky selected-scenario header stays hidden.

- Mobile payment modal z-index/scroll coverage, save-to-notes quick-save filtering, trainer result placement after correct answers, and Tools in-composer send-button layout.
- Mobile award viewport placement, mobile mistake dictionary bottom scrolling, compact Roleplay active state, and composer-level save-to-Notes placement.
- In-app Back navigation on desktop and mobile, plus the visible active-Roleplay choose-another-scenario action.
- Public-site Playwright coverage in `site-react/e2e/public-site.spec.ts` for the shader landing, no public `/app/v2` header link, theme toggle, dark legal language select readability, and `@NERIVAapp_bot` contact card.
